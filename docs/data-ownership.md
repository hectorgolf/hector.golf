# Who owns which field

_Decided 2026-09-12._

Every field in Hector's data has, or will shortly have, two possible writers: a scheduled job and a
human in the admin UI. This is the rule for which one wins, decided before the admin UI could write
anything, because the failure mode is silent — an edit that reverts overnight looks like it was never
saved.

## The rule

Fields fall into two kinds, and the kind decides the owner.

| Kind | Owner | CI behaviour | Human behaviour |
| --- | --- | --- | --- |
| **Derived** — computed from a source of truth elsewhere | CI | Recomputes freely, every run | Sets a *separate, explicit* override that wins at render time and can be cleared |
| **Authored** — written by a person, or generated once on their behalf | Human | Fills only when empty; never overwrites | Edits freely |

The distinction is not new. `update-player-club-memberships.ts` already assigns `club` only when the
field is empty, which is exactly the authored rule, arrived at independently because it was obviously
right for that field. This generalises it.

## The fields

| Field | Kind | Owner | Notes |
| --- | --- | --- | --- |
| `handicaps.json` history | Derived | CI | Scraped from WiseGolf. Never hand-edited |
| `player.handicap` | Derived | CI | A cache of the latest history entry |
| `player.handicapOverride` | — | Human | **New.** Wins over the derived value; empty means "use the real one" |
| `event.buckets` | Derived | CI | Recomputed twice daily for upcoming events |
| `event.bucketsLocked` | — | Human | **New.** When true, CI leaves the buckets alone |
| `player.biography` | Authored | Human | Generated by Gemini, then owned by whoever edits it |
| `player.biographyLocked` | — | Human | **New.** Set on edit; cleared by the admin UI's "regenerate" button |
| `player.misc` | Authored | Human | The prompt hints. CI reads, never writes |
| `player.club` | Authored | Human | Already correct: CI fills only when empty |
| `event.results.teams` | Authored | Human | CI back-fills only when absent |
| `leaderboards/*`, `clubs.json` | Derived | CI | No human writes them |

## Why the override is a separate field

The obvious implementation is to let a human write `player.handicap` and have CI stop touching it.
That is wrong, and quietly so.

`update-handicaps.ts` has been writing `player.handicap` for years, and **40 of the 45 player files
carry a value today**. Nothing records whether any given one came from a scrape or a person. The
moment the field is reinterpreted as "the human's override", all 40 become permanent overrides and
every one of those handicaps freezes — with no error, no warning, and no way to tell which were
deliberate.

A new, empty field has no history to misread. `handicapOverride` starts unset for everyone, so
"unset" unambiguously means "nobody has overridden this", and the same reasoning gives `bucketsLocked`
and `biographyLocked` rather than overloading the fields they guard.

## The bug this fixes

[`players.ts`](../astrosite/src/code/players.ts) resolves a handicap as `handicapOverride ||
handicapFromAPI` — it already treats `player.handicap` as an override, and carries a `TODO` saying
the resolution is unsettled. But `update-handicaps.ts` writes that same field on every run.

So the override is overwritten by the thing it is meant to override. Correct a handicap by hand today
and it reverts within 24 hours, silently. This is live, in Git, now.

It is deliberately **not** fixed in the current JSON pipeline. The fix is a schema change plus a
migration of 40 records, and doing that against files that are about to move to Firestore means doing
it twice. It lands with the migration, and it is written down here so it does not get lost.

## What the admin UI owes this

- A derived field renders the real value, with its override shown as an override and a visible way to
  clear it. Not a text box that silently shadows reality.
- An authored field is just editable.
- "Regenerate biography" is an explicit action. It clears `biographyLocked` and re-runs generation —
  the scheduled job never takes an edited biography away from you.
